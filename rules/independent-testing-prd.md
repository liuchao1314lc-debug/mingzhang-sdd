# PRD 阶段完整产物的独立评价

本文件承接 [独立测试规则](independent-testing.md) 第 5 节；通用评价要求仍沿第 1—4 节。

## 5. PRD 阶段完整产物的独立评价

### 对象、输入与分工

本项检查 PRD 阶段完整产物是否准确、完整地把已确认要求转成可理解、可验收的规格。评价状态（通过／失败／未执行／未安排）随报告与交接记录；未执行须用户明确接受风险、影响与交接，并给最小评价范围（核心任务＋权限／异常＋验收＋追踪），不宣称整稿独立通过，也不自动成为阶段硬门。在完整稿形成、作者自检之后，提交用户作指定版本阶段确认之前安排；需求澄清／暂存时不逐批启动。已通过的历史 PRD 不因本规则新增自动重开。独立评价的通过不替代用户确认，也不证明未来产品已实现或真实行为已验证。

评价方先依据有效 MRD／等效上游、本阶段确认需求及变更／取舍、产品定义基线（含产品类型）、目标项目已明确采用的 PRD 成果约定，固定判断依据，再开展正式稿件核对。成果约定须给具体位置／采用依据；使用本技能 PRD 方法时，对应[第 2—4 节](../skills/prd.md#2-从用户任务展开具体行为)的行为、验收／追踪及成文要求，不以被测稿或作者自检清单补造标准。

固定的是已有需求依据，不要求先批准被测 PRD 才能评价。稿中自行新增的要求／验收不能反向成为正确性依据。上游未决定的关键问题交用户裁决，评价方不替用户补业务或放宽要求。

先前已读过该稿须披露接触范围，阅读本身不使评价失效；仍须符合第 1 节独立设计和未参与编写的责任边界。

作者提交指定版本的完整产物清单：PRD 正文、实际拆出的业务／异常／非功能／验收／适用模型契约正文、需求追踪及需求路径入口引用（含具体 MRD／经确认等效依据、原始目标及有效变更）、本阶段配套的必要决定／变更／确认状态、计划验证与交接说明。沿现有载体列路径／版本／章节及对应来源，不要求拆成多个文件。评价方依据确认清单和阶段要求核产物清单是否完整，不能接受作者漏列某份正文来缩小范围；缺失必需产物本身是评价对象，不能从清单删掉后称全部通过。

首次评价覆盖这份完整产物的全部本版需求、必要分支、验收及跨条目关系，不仅是当前首功能、新改的几行或抽样。MRD 和确认记录供核来源及一致性，不对其整份质量重新测试；架构／模块／组件／UI、代码、模型执行、宿主接入、市场效果不属于本项。尚未进入本版的事项核其有效取舍与状态，不要求实现。产品计划中的后续测试只评价其是否可据需求执行，不在本阶段运行那些测试。

用户决定未定业务、范围变化、评价方及许可、阶段是否通过；作者交完整产物和来源并负责获准整改；评价方独立核覆盖、执行和报告，依第 1—4 节保持职责与证据独立。评价方不能一边改稿一边签独立通过；作者自检只作补充。

### 覆盖、方法与原始材料

评价方在项目已有评价／证据载体独立列“固定要求及依据 → 对应产物位置或缺失 → 核对操作／用例 → 由要求推导的预期 → 观察／证据位置”。计划中未核的位置可标待定位，正式评价的实际落点及结论记执行报告，不回改原计划。覆盖按实际适用内容组织：

| 核对对象 | 本阶段的具体操作 |
| --- | --- |
| 需求来源与完整性 | 从具体 MRD／经确认等效上游、本阶段已确认任务／需求及有效变更逐项找到行为及验收落点，反向核稿中内容的来源／范围；共享内容核各来源及实际承接子集，核移出理由和确认状态；并核目标、产品类型、范围／非目标是否相对已确认基线漂移，不能只查编号数量或接受作者映射代判 |
| 已确认平台约束与未知 | 从 MRD 产品类型基线或架构平台核查记录取适用约束，核 PRD 行为、异常、验收、计划验证是否承接；无官方依据的未知不代确认 |
| 用户任务、行为与可理解性 | 按稿中角色、前置、输入、操作和响应走到结果，核核心任务真正展开、人与产品责任清楚，前置需求本版有效；指出会导致不同操作／结果解释的歧义及影响，不能靠评价方自行猜测补齐 |
| 相关异常及状态／数据／权限 | 对已确认或有效方法要求适用的失败、取消、超时等分支，核触发、可见结果、影响和后续动作；不为不适用业务硬加分支 |
| 验收与适用非功能／模型契约 | 从固定要求自行推导场景，核稿中预期是否忠实、可观察、有验证条件；数值／边界有确认依据，不能采用作者的自定成功线 |
| 追踪、跨条目一致与交接 | 按[同一关系方法](../references/traceability.md)独立核来源—需求—验收—计划验证的双向关系及其承接含义，沿固定具体依据核回原始目标与有效变更；结构齐全仍须对照目标、范围、条件及验收，核术语、权限、状态、前后条件无冲突；稿中被当成本版有效要求／验收的新增内容须有确认来源且符合范围，拟议／待决／假设／未验证与确认分开，交接能定位有效规格 |

这些是适用核对对象，不是要求所有产品具备全部业务类别的新模板。每项具体用例仍须指向第 1 节的固定要求；正文通读、表格普查与链接检查可辅助定位，不能代替逐项语义判断和完整覆盖。人工沿规格推演应标“文档语义核对／纸面走查”，不冒称产品运行。

正式评价前说明产物清单、固定依据、覆盖与排除、逐项人工阅读／对照／推演操作及辅助命令。纯人工部分明确“无程序测试命令”，列实际工具、文件／章节、操作顺序和记录方式；用脚本时另列准确命令／参数／目录。先准备方案所做的读取不计正式通过证据。

在首项正式评价操作之前完成第 2 节保全：保存评价计划、覆盖关系、全部用例／预期／人工操作说明及存在的脚本原件，与执行记录分开；同时绑定可恢复的指定产物版本和固定依据，沿已有不可变版本或获准内容副本，不只记版本名／哈希。人工评价不能等读完判定后才补存方案；执行后的改动沿第 2 节保留旧文件及新版本。正式评价不改被测稿；稿件或依据变化时停止受影响项，核旧证据有效性再按第 4 节接续。

### 判定、整改与交接

实际读取／对照／走查后，逐项记录固定要求、正文位置、预期与观察、原始依据及第 3 节结论。已确认需求被遗漏、核心行为未展开、适用异常无结果、验收违反固定要求、正文冲突／关键行为存在影响结果的歧义，或无已确认来源／超出本版范围的内容被当成本版有效要求或验收，或产品类型／目标／范围／非目标与已确认基线不一致，是产物不符合要求，记验证失败。明确标为拟议且未进入本版有效规格的建议不因尚未确认判失败；资料未取得、工具读取失败、用例错误或本次未核覆盖，记证据不完整。两者可并存，不能把已证实遗漏改称“待以后测试”，也不能把评价方没测到判为产品失败。

整份产物的通过须覆盖清单中的全部必要内容且评价有效；结构／链接通过、作者自检通过或部分需求通过都不足。本版必要行为／权限／验收仍有影响结果的未决项时，不能形成整份通过结论；已经明确行为、只待后续验证的假设按[PRD 方法第 4 节](../skills/prd.md#4-形成实际-prd)核条件和验证安排，不混作未定业务。报告完整字段沿[第 3 节](independent-testing.md#3-执行事实结果与评价有效性)，PRD 部分关联完整产物清单及需求覆盖，之后才交用户作阶段决定。

发现问题先按共用根因规则定位原因和最小完整影响范围，交作者获准修正；未定业务交用户，不由评价方改稿代决。整改重测按第 4 节检查未解决问题、改变的需求／分支和有因果依据的关联验收／追踪；同一 PRD 文件不构成全稿重测理由。称为纯文字纠错的改动先比较实际差异，核行为、范围、验收、权限及追踪含义是否改变，再说明受影响核对／旧证据沿用依据；名称本身不能免检，语义改变则按实际影响重测。未受影响的首次证据有效才可沿用，覆盖有缺口不能以局部重测填成整稿通过。用户确认绑定实际版本，后续架构仍核独立授权。
