# 阶段交接包组织提示

本提示只组织已有对象的引用，不新增需求、存储或第二权威；字段与状态规则唯一见 [阶段交接物格式](../../references/stage-methods.md#阶段交接物格式)。按阶段实际裁剪，缺失项写状态，不写成散文清单。

## 最小结构

| 字段 | 填什么 |
| --- | --- |
| 上游依据 | 本次直接消费的有效上游对象／条目＋固定版本＋确认范围；沿需求路径追溯至 MRD 或经确认等效依据 |
| 承接条目 | 需求／验收 ID 与本次承接子集、理由 |
| 本层产出 | 成果对象、版本、状态、边界；状态用语沿阶段交接格式 |
| 异常与后果 | 从 PRD 起适用；相关业务异常在 PRD 明确、下游引用；待决列影响；技术／接口／交互细节留对应设计阶段；启动／MRD 无业务异常时填“本阶段尚无需细化”及依据 |
| 验收与验证 | 判据、计划／执行状态、证据定位 |
| 待决与未验证 | 未决项、影响、解除条件 |
| 下一层输入与许可 | 下一层动作、输入、所需许可、等待对象 |
| 路径引用 | 需求路径入口或本阶段实际适用依据 |

状态用语、产出生命周期与许可沿 [阶段交接物格式](../../references/stage-methods.md#阶段交接物格式)记录；本模板不重列。空引用须说明原因；不复制正文，不新增文件或协议。

## 示例（模拟，不是当前项目需求）

> 上游依据：MRD r1 的 R-01 与范围条目（已确认）；  
> 承接条目：R-01、A1；  
> 本层产出：PRD r1（候选）；  
> 异常与后果：失败后保留草稿、不对外发；取消后是否保留待决，影响架构中的草稿存储／清理设计；  
> 验收与验证：A1 可观察，用例计划未执行；  
> 待决与未验证：取消后草稿保留规则待用户决定，解除条件为得到决定后回写 PRD；  
> 下一层输入与许可：交架构前需 PRD 指定版本确认与架构许可；  
> 路径引用：R-01 路径入口（见 traceability 第 5 节）。

填写人可在既有交接记录中引用交接双方、确认依据、确认时点与接收状态；不新增必填字段、不另建台账。示例只说明字段用法，使用时替换为当前真实对象与确认依据。

### 示例二：架构→模块（含框架复用与产品类型基线引用，模拟）

> 上游依据：PRD r2（已确认）＋产品类型基线（agent／Web／私有云／内部员工／对话式，引用 MRD r1）；
> 承接条目：R-02、A2；
> 本层产出：架构 r1（候选）＋框架 A 核查清单（可复用能力、限制、缺口、证据）；
> 异常与后果：未核“多工具并行”不假设可用，列入待决；
> 验收与验证：复用边界与模块输入已列，验证计划未执行；
> 待决与未验证：框架版本确认与未核能力；影响：模块的接口、状态与测试输入中涉及框架能力的部分暂不能固定，未核能力不得写成可用；解除条件：固定版本并补核后回写架构，或经用户确认排除本轮使用；
> 下一层输入与许可：架构指定版本确认且已有模块许可后，按已核复用边界接续；许可未取得则等待。
> 路径引用：R-02 路径入口。

填写路径引用时按 [traceability §5](../../references/traceability.md#5-交接与评审的路径入口) 给出需求标识、固定版本、确认状态、产品类型基线与下层节点；上例“路径入口”只作示意。

### 示例三：UI→开发（含演示范围，模拟）

> 上游依据：PRD r2（已确认）＋组件契约 r1；
> 承接条目：R-03、A3；
> 本层产出：UI r1（候选）＋流程／状态文案／样例；
> 异常与后果：失败与取消状态已映射；未知状态提示待验证；
> 验收与验证：纸面走查已做，目标用户演示未执行；
> 待决与未验证：演示参与者与范围未定；影响：开发输入的体验验收样例与演示证据暂不能固定，解除条件为用户可安排目标用户演示；
> 下一层输入与许可：UI 指定版本确认且已取得开发许可后接续；许可未取得则等待；
> 路径引用：R-03 路径入口。

示例只说明字段用法，不新增框架能力事实或默认业务。
