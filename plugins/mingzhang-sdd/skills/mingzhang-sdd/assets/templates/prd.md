# PRD 组织提示

沿用项目已有规格结构；新建时可按下列内容整理，删去不适用提示。字段只帮助写清已获准内容，不生成业务或默认目录。

1. 对象、版本／身份、本次模式及有效目标／范围／非目标和来源。
2. 用户任务：角色、触发／前置、输入、操作、响应、结果及关键异常节点。
3. 稳定需求：来源、归属、前置需求、具体行为、优先级／理由、版本／确认状态。
4. 相关业务对象／数据边界、权限、状态与异常后果；模型产品只补实际适用行为契约。
5. 关联需求的验收：前置、事件、可见预期、证据与验证方式；非功能要求注明作用范围和数值来源。
6. 来源任务到需求／验收／计划验证的追踪；语义核对、关键歧义、待验证假设及用户实际决定。
7. 本次变更／检查／未完成、指定版本确认身份及后续交接输入。

核心任务不能留成“支持某能力”；异常要写用户看到什么、能做什么。编号、表格或模板存在不代替正文完整。歧义材料及确认操作沿包内共用规则，不另维护裁决清单。

起草前引用当前需求记录及本阶段收全确认；成文后核每项记录对应的实际行为／验收落点，未纳入项说明用户有效取舍依据。
