# PRD 组织提示

沿用项目已有规格结构；新建时可按下列内容整理，删去不适用提示。字段只帮助写清已获准内容，不生成业务或默认目录。

1. 对象、版本／身份、本次模式及有效目标／范围／非目标和来源。
2. 用户任务：角色、触发／前置、输入、操作、响应、结果及关键异常节点。
3. 稳定需求：来源、归属、前置需求、具体行为、优先级／理由、版本／确认状态。
4. 相关业务对象／数据边界、权限、状态与异常后果；模型产品只补实际适用行为契约。
5. 关联需求的验收：前置、事件、可见预期、证据与验证方式；非功能要求注明作用范围和数值来源。
6. 具体 MRD／经确认等效需求依据到需求／验收／计划验证的追踪，说明本层怎样承接目标、条件和边界；语义核对、关键歧义、待验证假设及用户实际决定。
7. 本次变更／检查／未完成、指定版本确认身份及后续交接输入。

核心任务不能留成“支持某能力”；异常要写用户看到什么、能做什么。编号、表格或模板存在不代替正文完整。歧义材料及确认操作沿包内共用规则，不另维护裁决清单。

起草前引用当前需求记录及本阶段收全确认；成文后核记录对应的实际行为／验收落点，未纳入项说明有效取舍依据。

## 最小示例（模拟，不是当前项目需求）

> R-01 导出任务：已确认问题为“月底报表交付来不及”；用户提出的“加导出按钮”暂标方案建议。首版行为：用户选择当前报表并导出；导出中显示进度，失败保留已选条件并允许重试；成功后提供文件。验收：A1 正常导出可观察、A2 失败可恢复；来源 MRD r1 的 R-01；下一阶段输入见交接包。

示例只说明一条任务怎样写行为、异常与验收，不生成默认业务或完整 PRD。

关系、溯源和专业交接沿[需求贯通方法](../../references/traceability.md)，沿用项目已有唯一追踪入口；本模板只作组织提示，不另建关系规范或重复映射。
