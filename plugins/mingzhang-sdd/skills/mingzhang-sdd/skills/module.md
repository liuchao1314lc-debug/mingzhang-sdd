# 模块：职责与协作

## 是什么、做什么、怎么做

模块是系统内有明确职责的逻辑边界；不必等于目录、服务或 Agent。把有效架构细化为职责、状态归属、依赖与协作，使一个当前任务能跨模块完成。先读 [阶段组织](../references/stage-methods.md)，用实际任务走查设计。

## 1. 输入、模式与责任

核有效 PRD／验收、架构／决定／系统验证策略、平台规则核查结果与约束／待办（如有）、现有模块和本次新建／修订／只读范围。Agent 提取责任、设计协作并核覆盖；用户决定影响范围或责任的重要取舍及指定版。关键架构未定时标依赖，不用模块反推产品要求。

第2节划分责任前先读 [需求贯通](../references/traceability.md)，需求关系沿该方法维护；风险／试验、规划与实际入口仍沿 [成果载体](../references/stage-methods.md#成果入口与验证载体)，注明受影响模块；无有效风险载体时交待验证事项及影响，不另造模块风险记录。设计形成不预填代码、测试或用户通过。

**本步落点与继续条件：**输入／版本及本轮任务进入模块记录；当前链路与架构边界足够明确后划责任。

## 2. 划分职责与状态

按业务任务和失败责任定当前需要的模块，给稳定标识、职责／边界、具体 PRD／验收子集及架构对应，说明本模块承接的责任和理由，并沿关系反查具体原始要求；共享责任保留各来源及协作汇合，不先设计全部未来模块。适用非功能明确谁实现、谁协作、谁汇合判断，不只放整节链接。

对关键数据／状态明确权威、读写者、产生／改变时机及交接，不多处维护当前状态。向用户展示当前任务如何分工，争议决定后再依赖它细化；正常分工内连续推进。

**本步落点与继续条件：**模块条目和状态归属写在模块稿；核需求归属及权威不冲突、影响分工的决定已取得后细化协作。

## 3. 依赖与协作契约

明确工作发起方向与被依赖职责；返回／向上请求单独说明与主发起图关系，不误当循环或静默漏边。发现循环定位实际原因，必要时调整责任／契约，不用新增中间层遮盖问题。

每个必要协作给调用条件、输入来源、输出／负责人、异常／超时／取消／未知、权限和必要资源约束，引用架构唯一接口。对唯一提交、重复／并发确认等关键保证，当前层明确谁提供状态条件或竞争门禁、保证什么、失败可见后果；只有取得提交资格者才能调用业务写入；具体锁、CAS 和字段留组件，但保证本身不能全部下放为后续细化。需要确定性事实时从 Agent 已注册工具中选择实际接口（沿[工具使用与检查](../references/checking.md)），普通读取只支持其已覆盖条件；分项判断引用真实工具返回，不自造检查程序，也不把读取成功当成全部检查完成。

**本步落点与继续条件：**依赖关系和接口引用进入模块稿；核发起／返回及必要输入输出可连通后走查。

## 4. 当前端到端任务走查

依当前授权选择代表任务，说明为何能验证关键责任；选择影响范围时先给用户建议。逐节点核发起者、输入、协作、状态／异常与汇合结果，记录具体模块落点，覆盖正常及相关缺失／失败分支；声明的分支必须实际走到。走查须带一组具体代表性输入（正常值与至少一个重复／失败值，含可区分行身份或对象标识），逐步推到最终可见结果、数据／状态后果及失败责任人；涉及行式处理时给拒绝／写回行数，异常按当前任务相关分支选择；不能只写流程表、字段约定或把具体输入留到开发／联调。若当前授权无法提供具体输入，标缺口并说明阻断，不能记走查完成。

这是设计走查，不能说真实执行通过。核具体要求到模块／协作汇合的覆盖关系双向一致、共享来源无遗漏、接口只有唯一依据、过关条件能定位到正文；按 [检查顺序](../rules/execution.md#9-检查动作与结论)核完再报，缺项按根因规则修正。

**本步落点与继续条件：**在模块稿保存实际走查节点与缺口，核所声明分支均有落点；关键职责未闭合先修正，闭合后交付指定稿。

## 5. 完成与组件交接

交模块职责、数据权威、依赖／协作及实际走查结论和限制，用户确认指定版本。获准后向 [组件](component.md)交当前功能、所属模块、具体要求与模块责任关系、唯一接口依据、异常责任、系统策略及平台约束与待办（如有）；仍有内容前置明确限制。未获后续许可停止，不建源码／安装。恢复沿当前模块和受影响任务，不因改版重划全部责任。

交接给组件的交接包按[阶段交接物格式](../references/stage-methods.md#阶段交接物格式)组织：PRD／架构与确认、需求子集与模块责任、模块稿版本、异常与失败责任、平台约束与待办（如适用）、组件输入及路径引用。其余通用字段、五类状态与模板沿格式节。

## 6. 规则与失败处理责任

每条当前任务中的规则明确一个业务／状态权威及实现、协作、验证和失败升级责任，跨模块共享时指定唯一维护者及引用位置。Agent 给出分工理由，用户决定影响产品或范围的重要取舍；实现单元不能自改业务标准，模块职责不等于真实执行者已委派。

将责任、前置及待决影响交组件合同；设计涉及的唯一需求与架构来源必须可定位。责任缺口回本层／架构解决，业务语义缺口回 PRD，权限冲突沿 [三类约束](../rules/core.md#三类约束与采用边界)停止相关动作，不让开发者自行填空。

**成果最小清单（完成前核对）：** ①模块职责与边界（含不做什么）；②状态／数据权威与失败责任；③依赖／协作契约、关键保证的承担者与依赖图（如适用）；④owner／团队映射或未知；⑤接口目录（组件输入）；⑥当前任务走查（含具体代表性输入、最终可见结果与数据／状态后果）；⑦非功能落点。缺①②标缺口，不默认记模块完整。
