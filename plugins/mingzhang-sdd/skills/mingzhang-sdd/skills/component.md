# 组件：可实现的单元与契约

## 是什么、做什么、怎么做

组件是模块内支持当前功能的可实现、可验证单元，技能中的工作步骤也可以是组件。先定单元与所属模块，再细化输入输出、状态／异常、替身及用例，走查后交 UI／开发；不预先设计未来所有类。共用方法见 [阶段组织](../references/stage-methods.md)。

## 1. 输入、裁剪和分工

核有效需求／验收、架构、模块／接口、当前功能及新建／接续／修订／只读模式。只读评审交意见，不写契约。每单元明确单一模块归属、需求来源和职责；跨模块责任回模块处理。Agent 完成契约与走查，用户决定影响产品／范围的重要取舍及指定版，内部明确技术字段不逐项要求审批。

风险／试验、唯一追踪和规划／实际位置沿 [成果载体](../references/stage-methods.md#成果入口与验证载体)，不另建组件风险系统；预计实现位置明确为规划。

**本步落点与继续条件：**本轮输入／模式和限制进入组件记录；所属模块与当前任务明确后定单元。

## 2. 确定当前单元

从当前任务关键责任、输入和失败模式选择需要拆分的单元，说明拆分收益；不强制一类责任一个组件，不把组件自动变成服务／多 Agent／状态库。向用户展示从输入到结果的分工和重要分支，必要决定取得后细化。

**本步落点与继续条件：**单元、单归属和拆分依据进入组件稿；核职责与输入／失败模式足以区分且重要决定已取得后细化合同。

## 3. 细化接口与状态

对实际消费的接口定义类型、必需／可空条件、默认或无默认、范围／来源、版本与异常；调用侧与采用侧一致。空值、缺字段、不完整证据、不可解析和版本不支持分别明确结果及影响，不能留给开发猜。协议结果与业务检查结果的标识／数量／采用范围分开说明。

<a id="consumer-compatibility"></a>

契约变化影响既有调用者、保存数据或历史证据时，Agent 先引用架构的[兼容／迁移设计](architecture.md#compatibility-design)中的决定，再按以下顺序细化：

1. 找出实际消费者及其版本、旧请求／回执／存量对象，定位原承诺和本次改变的字段、默认行为、状态或错误含义；没有既有消费者时注明实际情况，不虚构旧客户端。
2. 逐项说明旧输入或对象在新版下得到什么结果、哪些承诺保留、哪些不支持或需要迁移／重新确认。版本标签不能代替行为判断；上游未承诺或存在冲突时，向用户说明影响与选项，必要决定前不默定兼容，也不靠实现反改架构。
3. 选择实际可能且受影响的新旧组合，明确调用者、契约／对象版本、预期可观察结果及适用条件；第4节用例引用这些契约预期，开发按同一组合验证。语义与条件未变且证据仍覆盖本次对象的组合沿用有效证据，改变的只补相关验证，不要求所有历史版本全组合测试。

消费者关系及结果约定写在当前组件契约，用例正文仍只在第4节维护。关键旧输入／对象结果未定则暂停依赖实现，已明确且独立的部分可继续。

状态说明前后条件、谁改变／观察、失败／超时／取消／重复／未知的结果和责任。模型拟议、动作发起与真实返回分开；真实副作用未知先核原动作，不重跑来试探。仅相关动作定义释放、预算和用量未知；单元不改写系统权限或有效标准。

超时或取消不证明外部动作未发生，不能预设一律可回滚或幂等；按真实外部能力定义核对、补偿或升级处理条件及负责人。

**本步落点与继续条件：**字段、状态和异常唯一维护在组件契约位置；核调用／采用侧无关键歧义后制定用例，语义未定先补齐。

## 4. 依赖、替身与用例

标实际外部依赖、可用替身、测试输入／返回和失效条件；替身成功只验证指定局部，不证明真实调用。按需求选择正常、相关边界、错误、权限、取消、未知、重复和资源释放用例，写前置／动作／预期、观察位置与真实执行方式。

用例正文只在一处维护，引用系统验证策略，不另造验收评分。用例计划与执行证据分开，未执行保持未执行。

**本步落点与继续条件：**替身说明和用例正文进入组件既有位置；核每项预期可观察且真实／替身边界明确后走查。

## 5. 检查与走查

沿当前端到端任务逐节点核单元、输入、调用、结果采用及异常汇合。接口应足以支持实现；语义未定的关键空值／异常／采用边界在本层补齐，不靠下游猜测。按 [检查顺序](../rules/execution.md#9-检查动作与结论)核实际契约和用例关系后报告，发现根因回所属责任修正最小完整范围。

**本步落点与继续条件：**走查结果及缺口定位在组件稿，不是执行日志；关键接口已闭合后交付，否则修直接关联再查。

## 6. 完成、交接与恢复

交指定组件版、实际设计走查、用例计划和限制，用户确认该版。获准 UI 时交用户可见状态、动作及后果给 [UI](ui.md)；获准开发时交字段合同、异常／副作用与用例给 [开发](development.md)。设计确认不表示源码／真实调用已获许可。停止在当前范围；恢复核契约版本、调用者和失效证据，沿用有效确认。

## 7. 开发前契约交接

在当前开发包合同的[实施进入条件](../references/stage-methods.md#实施进入条件)交付固定需求／设计输入、正常及相关异常结果、权限／数据后果、实现与失败负责人、可观察验证及未决影响。字段、状态与异常正文仍在本组件契约，合同只引用，不复制规则。

Agent 核接口消费侧和实现侧能否判断结果，用户决定重要业务／范围取舍及指定版本。当前包关键语义不明时列缺口及解除条件，暂停依赖实现；技术探索明确试验身份，不能记包验收或用试验补造原产品确认。
