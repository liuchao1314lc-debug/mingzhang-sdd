# 项目资料、历史与版本治理

本文件承接资料身份、当前摘要与历史、项目版本计划与升版判定；按入口及各节实际触发按需读取：阶段交接、成果更新、版本变化、历史入口被引用、用户要求核对或交付构件等。阶段组织、[阶段衔接总表](stage-methods.md#阶段衔接总表)与[阶段交接格式](stage-methods.md#阶段交接物格式)见 [阶段方法](stage-methods.md)。

## 当前摘要与历史

当前入口和运行文件只维护对象身份、适用范围与采用／结果指针；提交与核验的当前状态只在目标项目既有当前状态区（如项目已有 STATUS 类追加状态记录）及既有证据的固定对象结果节维护，其余文件不得复述。历史记录和原始结果保留原对象，不用时点标签把失真的句子继续当当前说明。检查具名状态落点的对象绑定指针及有无失实状态自述，方法正文中的规则、类别与示例不作为项目当前状态扫描；工具不能判任意语义或替用户批准。

内容生命周期（草稿、当前、已替代、封存、历史证据）与保存身份（已提交、已跟踪未提交、未跟踪、有意排除）分别记在项目已有权威索引及状态，文件自述只引用；已有载体不是 Git 时映射为已发布／草稿／已归档／不可得等现有状态，允许标未知并给依据，不为登记新建 VCS 或 schema；规则的变更／采用依据随对应决定记录，历史批准只绑原对象。状态记录行号及数量注明提交或工作树观察版本，不能统一偏移换算；目录存在、原位保存、入库归档分别判断。

实际触发点：阶段交接、成果更新、版本变化、历史入口被引用或用户要求核对时，按本节核对内容生命周期与保存身份；无法确认的历史身份不写成当前事实，相关当前判断等待。

### 历史文件操作入口

1. **判定**：阶段结束、对象被新确认版本替代、需要封存或保留历史证据时，先判定内容生命周期（草稿／当前／已替代／封存／历史证据）与保存身份；**没有有效的结束、取代或封存依据，不将仍有效对象提前标为历史；原确认状态保持**；历史不因目录移动自动改变身份。
2. **登记**：在项目已有索引／状态补原对象身份（提交或路径／blob／内容指纹）、生命周期、取代关系及依据、现行入口、适用范围与失效部分；**保留可恢复的原对象及固定身份，不回改旧批准或原始结果；迁移另核规格、范围与许可**；更正以接续记录补充。
3. **核对**：交接、交付、恢复或引用历史前，核“现行入口→索引→原对象”一致；历史中的“当前／下一步／必须做”只属当时；有效决定与现行正文冲突时以有效决定为准；无法确认的身份保留未知，暂停依赖动作。
4. **不动作**：分类、归档或索引不授权删除或迁移；移除、覆盖或清理仍须对应规格、范围和许可。

## 项目资料与版本治理

本方法用于目标项目各阶段的资料整理、版本交接和获准交付。沿已有文档、合同和记录维护，不要求固定文件名、目录、登记 schema 或新台账；只读模式只报告建议落点。Agent 在授权内起草、维护、核对并报告，用户决定重要职责／范围／兼容取舍及指定版本，独立评价和发布责任按实际安排登记，不从文件存在或角色称谓推定委派。

### 文件与信息

先明确每份文件的主要职责、唯一正文、维护者和需要谁决定；小项目可在已有文件中用具名分区隔离职责，不为分层强制拆文件。职责与更新触发如下，更新均受当前写入许可约束：

| 资料角色 | 保存内容与边界 | 更新触发 |
| --- | --- | --- |
| 稳定定义与规则 | 产品定义、长期约束及专题机制；不记录每轮进度 | 对应有效决定或机制变化 |
| 当前事实与职责入口 | 当前任务、风险、下一步及已核实的实际职责；状态与地图分别维护自己的内容 | 事实、实际入口变化或交接 |
| 功能合同 | 当前功能／开发包的范围、输入、交付及验收依据 | 该功能范围、前置或契约变化 |
| 专题合同 | 跨功能复用的领域机制及边界；功能合同引用，不复制 | 该专题机制或责任变化 |
| 历史证据 | 原对象、当时决定、实际执行及结果；不充当当前任务清单 | 结束或被替代时建立索引；更正用接续记录，保留原件 |

文件角色与规则归属沿 [core 三类约束](../rules/core.md#三类约束与采用边界)与 [core 资料身份与冲突裁决](../rules/core.md#资料身份与冲突裁决)；不能因为都叫“规则”就放入工具约束目录。稳定规则的来源、适用范围与实际采用关系沿[规则职责与采用](stage-methods.md#规则职责与采用)，当前授权／状态及固定结果沿[当前摘要与历史](#当前摘要与历史)，导航和摘要只指向它们。存在结构化登记时，按文件逐项核正文指针所列键与该登记对应键集相等、无重复，不合并不同文件的键来掩盖缺项；项目未使用登记时不为此创建 schema。

接手从目标项目真实宿主入口开始，依次定位当前请求及许可、生效规则、当前阶段的有效规格／合同、实际成果与所需证据，再按任务查历史；沿已有阅读路线，不固定重建一套根文档。来源是示例、提案、外部反馈、原始观察还是有效决定须保持身份；日志／记忆和读取受阻的处理沿 core，不能用宿主摘要替代完整方法或正式授权。

历史文件中的“当前／下一步／必须做”仅属其当时对象和范围；在既有索引标明历史身份、适用对象、取代依据及现行入口，不回改旧批准或原始结果。部分条款／字段仍有效时逐项说明，只替代失效部分，不整份判废。生命周期与保存身份直接引用“当前摘要与历史”，不另定义；原位保存、入库归档和排除登记不能互相冒充。

源码、生成目录、分发制品、安装副本、外部公开树分别注明实际来源／版本、用途和核对依据；本地正文更新不证明其他副本同步，历史观察不证明当前仍存在或一致。仅在当前授权范围同步，未同步的明确其适用身份及影响，不手工改生成物来冒充重建。不按旧命名或静态引用计数判断可删：旧格式兼容、当前共用服务、诊断或动态测试样本分别核实际消费者；分类本身不授权清理，移除／迁移须有对应规格、范围及许可。

在接手时核入口／现行身份，相关修改后核直接引用、版本与取代关系，交付前核当前状态、实际对象与证据能否对账。沿[execution §9](../rules/execution.md#9-检查动作与结论)选择目标项目已有工具或人工核对，写明对象、实际结果和限制；不强制每轮新建检查器、全仓哈希或固定字节前缀。发现缺项、指针不一致或身份无法确认时，报告并暂停依赖判断，独立获准部分继续；结构可解析不证明语义等价或用户确认。

### 文件版本与产品基线

区分产品版本、流程文件自身版本、源码／候选身份、构建制品身份及接口／数据格式版本，不要求编号相同，不做全仓版本串替换；文档修订不自动升产品版本。流程文件在既有阶段稿及变更记录中关联实际内容、修订依据、适用范围和确认状态，具体记录及确认沿 requirements／execution，不另建一套版本台账。真实依赖属于相应源码／构建基线时，引用已有锁定文件或配置定位，不虚构依赖清单或强制采用统一编号规范。

对话讨论与未确认草稿可用可定位的轻量标识；交用户确认、采用、验收、发布或跨项目交接前，固定实际内容及范围，用可回读的提交及路径、不可变快照或内容指纹定位，不能只写日期、“本轮”或“最新版”。

实际操作点：①阶段完成或交接前固定本阶段成果身份并引用上游固定版本；②版本变化按影响重核，不静默换绑旧确认；③升版、发布或安装按实际决定与许可另核，不把本地通过当发布。编号相同而内容变化是不同对象；旧标识和确认仍属于原对象，新内容须重核受影响引用、证据及确认范围，不把旧指纹换绑到新内容。实际取证唯一沿[工具使用与检查的版本与返回](checking.md#version-evidence)，不另造算法。

多文件共同构成一个基线时，在既有合同／交付记录中列组成文件、各自固定版本标识、适用范围及来源／确认记录，并关联实际下游消费者；不把不同对象的局部确认合成全基线通过。每次交接核引用的正是该内容，未确认的必要输入明确限制。本表是交付前应固定／引用对象的唯一清单；阶段接续方向与许可沿[阶段衔接总表](stage-methods.md#阶段衔接总表)，不在此另列。开发前的上游链及后续承接如下：

| 阶段交接 | 本阶段应固定／引用的对象 |
| --- | --- |
| 启动接续 | 新建：目标、需求记录、来源／决定、未决；已有：现行需求、设计、实现、运行／发布版本与本次范围；没有同名文件不重启项目 |
| MRD → PRD | 有效目标、首版／非目标、约束、产品类型基线（含平台约束与未知）和成功依据的指定内容及确认范围 |
| PRD → 架构 | 当前行为、规则、验收及未决项的固定规格；需求改变先按 requirements 处理；独立评价状态（通过／未通过／未执行／未安排） |
| 架构 → 模块／组件／UI | 实际相关的系统／数据责任、接口与恢复依据；系统验证策略及其固定引用（可为独立文件）；框架核查结果与复用边界（如适用）；平台核查记录与约束／待办（如适用）；组件／UI同时引用相关PRD及彼此实际消费的契约，不假定十阶段严格线性 |
| 模块 → 组件 | 所属模块、当前功能、具体要求与模块责任关系、唯一接口依据、异常责任、系统策略、平台约束与待办（如适用）、实际走查结论 |
| 组件 → UI 或开发 | 字段合同、异常／副作用、用例计划、用户可见状态与动作后果、平台约束与待办（如适用）；按真实消费者分别交接 |
| UI → 开发 | 流程、状态／文案、输入约束、组件关系、验收样例、演示范围与未执行状态 |
| 开发包 → 联调 | 待测实现／环境、任务来源、局部证据、缺陷／未验证、框架复用依据与已核范围、平台待办、实施进入条件；不另建开发前置表；包内任务不各自暗换上游 |
| 联调 → 验收／迭代 | 待测实现或制品、构建／运行条件、有效验收依据及限制；用户验收结论、发布事实或未发布状态、缺陷与反馈；结果能对回实际受测对象 |
| 迭代接续 | 原基线、本次变化、新固定对象及其确认／取代范围，未受影响的有效依据继续沿用 |
| 首版／未发布版本范围裁剪或功能延期 | 按 requirements §3 与用户决定更新范围、验收与追踪，标失效确认与受影响包；产品版本动作沿项目已有规则，不自动等同升版；已发布版本的范围变化仍按不兼容／兼容处理 |

上游实质变化按[requirements §3](../rules/requirements.md#3-收全后起草)及[execution §10](../rules/execution.md#10-评审意见返修与成果确认)处理，沿用其纠错、确认和旧证据规则。沿已有“待同步正文”词汇记录受影响落点；实际写入核对后才记“已同步”，必要复核或指定确认尚缺时同时记“待复核”及对应对象，不把两种状态混为一项完成。同步过程中上游再次变化，保留本次实际同步的基线，对新变化重核影响，将相关落点恢复为“待同步正文”或保持受影响复核未完成；无关已完成项不回退，不静默改指针后沿用旧结论。

涉及可运行／可分发制品时，按目标项目已有构建记录保存：来源基线与相关构建条件（平台、配置及适用依赖）、生成时间、制品内容指纹；Git构建注明 buildCommit／buildDirty，非Git来源注明适用身份，不伪填干净状态。脏构建还须定位实际差异的快照或指纹，仅写 dirty=true 无法固定内容；缺身份时保持候选及证据不足。单文件取实际文件指纹，多文件制品明确清单范围、文件数及组合指纹，不默认散列整个开发仓库；不得从旧聊天复制身份。

同一目标、平台、配置及验收用途只保留一个明确的当前验收指针；比较版本、多平台构件及历史对象可并存，但标清身份与用途。替换前核旧对象来源并保留上一有效版本及可恢复依据，直至新对象验证后按许可切换；来源不明残留不覆盖、不复用或顺手删除。涉及数据迁移时先引用[架构的恢复依据](../skills/architecture.md#runtime-delivery)；无法回退的场景须先明确停止、核对和人工处置条件，不承诺失败总能恢复，也不自动回滚用户数据。

新版对已承诺支持的旧接口／数据负责提供有效读取或约定的迁移路径，不支持的对象明确拒绝及后果；改变支持范围先说明实际消费者、数据后果及取舍并取得必要决定，不以拒绝代替兼容承诺，也不默认永久兼容所有旧版。具体机制和组合验证分别沿[架构兼容设计](../skills/architecture.md#compatibility-design)与[组件消费者契约](../skills/component.md#consumer-compatibility)，不在本节另写迁移步骤或因旧名清理兼容层。

验收记录绑定实际受测对象与条件；发布或安装的是另一构件时，先核来源与内容对应关系及必要差异验证，不自动迁移结论。当前源码、验收构件的显示版本可与已发布版本不同，构建内容也可领先；领先、升版或本机刷新不等于发布。动作许可唯一沿 core，交付／安装／部署就位不等于验收；实际交付沿[联调方法](../skills/integration-testing.md#4-用户验收与获准交付)核准许对象、环境和回读。已发布对象不得在同一不可变发布身份下静默换内容；新内容须有可区分身份和适用验证，原报告、批准及发布记录保持原对象。

### 项目版本计划与升版判定

在既有合同／交付记录建立项目版本基线：当前产品版本标签与组成对象（规格／设计／运行内容／实现／制品／固定提交或内容指纹）、适用范围、确认范围及计划中的下一版本／里程碑。没有版本计划时按当前有效版本记录，不虚构日期或版本号；版本标签不替代内容身份，多文件基线按上文固定组成、来源与确认范围。

升版按变更性质判定；版本号方案沿目标项目已有规则，未约定时由用户决定，不默认引入语义化版本：

| 变更性质 | 版本动作 | 记录与权限 |
| --- | --- | --- |
| 产品行为、范围、验收或外部契约发生不兼容变化 | 由用户决定升产品版本；同步规格、设计、追踪与必要验证 | 旧版本原对象及确认保留，标取代与失效范围 |
| 向后兼容的新增能力 | 按项目已有版本规则决定次版本或功能版本；不自动发布 | 记录新增范围、验证及适用范围；旧版本继续有效 |
| 纯文字／等义整理、内部实现或证据补充 | **不因此类改动自动决定升版，按实际影响、项目已有规则及有效决定判断**；更新内容身份 | 保留原版本对象，不换绑旧确认 |
| 构建、安装、发布或部署 | 与版本判定分开，各自核许可 | 不因构建或安装自动升版 |

操作入口：交接、交付或发布前复核版本基线（版本、对象身份、包含与确认范围）；版本变化时说明受影响对象、旧版本历史身份及回退依据；发布、安装或部署前取得对应许可，不把本地通过或构建成功记成发布。文档修订不自动升产品版本；同一版本标签内容变化仍是不同对象。
