# 消息与需求沟通示例

以下均为模拟示例，需替换为当前真实对象、依据和许可；操作要求仍见 [用户消息组织](messages.md)。

开工定位仍按[execution第1—5节](../rules/execution.md)触发和核对。以下为模拟的活动报名文案评审示例，各项内容应由当前任务的有效资料和许可填写，在对应实质动作前实际发送。

阶段定位：UI／交互设计｜报名提交失败提示的文案评审；任务模式为只读评审。

项目归属：活动报名项目 → 报名提交失败后的提示与重试引导。

来源标识：当前用户请求要求只读评审；已确认PRD r3规定失败后保留报名信息并允许重试，UI草稿 r1是本次评审对象。拟提出的文案调整属于建议，尚未采用。

范围确认：只读核对UI草稿中的失败提示与上述行为是否一致，交付问题、依据和文案候选；本次不改稿、不实施页面或运行测试。资料不足的部分说明缺口，当前评审不扩大为重新设计报名流程。

以下为模拟示例，需要换成当前真实对象及范围，不是固定业务或已发生证据：

- 文件可读而内容不完整：“PRD r2 能打开，但还没有写清失败后怎样提示、用户能做什么。我会按已有修订许可补这段，再核对应验收；现在不能交为完整成果。”
- 改动集合不足：“PRD r2 已写入，但记录还不足以确认本次是否只改了允许文件。先补核这次动作的前后记录；正文候选可继续评审，改动范围暂不能说已通过。”
- 接口不足：“当前环境没有这项能力，因此这项还没有检查。我会说明缺少的能力、用途和影响，保留限制并继续不受影响的部分；能力可用前不把人工判断写成工具已检查。”
- 超时未知：“检查调用没有完整返回；我先核原进程结果。它不会因此重跑目标项目测试或再次写入文件，已有成果仍保留。”
- 额度到界：“草稿保留，但批准的调用额度已用完，改动范围尚未核完。我会停相关检查并交已有结果；恢复前先核原结果、剩余额度及许可，未知用量不会填成零。”
- 交付确认：“PRD r2 已写入，失败提示和后续操作已补齐；本次改动范围核对仍未完成。我会在已有许可内补查记录。你确认的对象是该版正文，范围证据缺口另保留；下一阶段是否开展另按你的授权。”

工具原始返回按宿主实际格式保留；人读摘要由 Agent 实际发送，不能改写原始事实或冒充原件。只在文件保存、消息草稿形成或链接存在时不算用户已看到；补发也不倒签及时呈现。

需求沟通也用真实记录表达，以下仍是模拟示例：

- 回述：“你说‘通过后就往下做’，我理解为确认这份成果的同时，也允许启动下一阶段；还是只确认成果，下一阶段另定？这会影响我是否开始后续工作。”实际回应前保持拟议。
- 专业转写：若用户明确只确认 PRD r2，交接写“确认对象：PRD r2 的指定内容；确认范围：本版行为与验收；下一阶段许可：未授予”。沿真实记录引用其回应，不把这段模拟文字当实际确认。新出现的重要结果仍须回述理解并交用户决定。
- 产品取舍：“首版有两个范围：A 保核心任务、B 加审批流。A 更快验证核心问题，B 会推迟上线约两周且增加权限复杂度；我建议先 A，B 列为下一版候选。请你决定本轮范围，未决定前不扩开发包。”
- 价值无基线：“首版目标中的复用率目前没有基线，也没有可用埋点；我会把观察数据需求带入 PRD，但上线后只能先标未验证；要不要本轮补采集，请你决定。”
- 独立评价未执行：“完整 PRD 已自检，但当前没有可用独立评价方。我会交评价未执行、影响范围和最小覆盖说明；你可以决定接受风险继续确认，或先安排评价。不能记成整稿独立通过。”

- 暂存：“你确认的‘取消后保留草稿’已保存到需求记录 R-03。保存内容是停止后续处理、草稿仍可编辑；已经发出的外部动作是否能取消还未确定，我会单独核对。”这句只能在实际写入并核对后发送。
- 冲突：“刚才新增的‘取消就删除草稿’与 R-03 的‘保留草稿’冲突，两者会导致不同结果。我建议默认保留，并提供用户主动删除；这需要你决定。相关取消规则暂不定稿，其他任务可以继续整理。”
- 收全：“目前这条任务的操作、取消结果和验收已列出，待决项已解决。请核对还有没有遗漏；你确认本阶段这份清单已收全后，我再起草正式 PRD。”已取得该确认就沿用，不再次提问。

以下两个模拟例子说明怎样沿真实回应识别决定，不新增确认节点或固定口令；前提是回应所指的对象／清单及范围可唯一定位，影响继续的冲突已解决：

1. 用户说“刚才清单就是本轮全部修改，按清单修 PRD，改完给我看”。这同时确认了清单内的修改内容、本次变更范围收全及该范围的修订许可。Agent 可在既有许可内修订和检查，不再逐项重复索取这些决定；修后 PRD 尚未形成／交付，不能登记修后版本已通过，也不扩大到清单外工作。
2. 用户在指定稿交付后说“PRD r7 这一版通过，下一阶段先不做”。这确认了 r7 的指定内容版本，Agent 不再重复追问该版是否通过；已有未变决定沿用。它不倒填其他版本／范围的确认，也不授权下一阶段实施。内容理解确认、范围收全、修订许可与指定版通过各自按实际对象判断，一次回应可以覆盖多项，但不能互相补造。
