# 宿主取证、检查调用与采用

本任务首次使用程序前读 [程序能力与示例](../scripts/README.md)及[包内检查合同](check-contract.md)。同一任务中版本未变、已完整读过的内容沿用；出现具体歧义再定位对应段落，不因每次调用或遇到引用重新读取整组方法。完整回执不是业务批准，参数不是用户许可。宿主 Agent 负责真实取证、固定入口调用和结果采用，不增加常驻运行器或五套检查逻辑。

## 1. 准备事实

在当前许可内观察开工版本、索引／工作区、未跟踪路径及允许修改对象的必要前状态；Git 项目只读观察，非 Git 项目沿已有文件与操作回执，不为检查初始化 Git。必要前内容只保留获准相关对象，不做全仓快照或全量哈希。本包支持的原始采集／保存顺序沿 [collection](collection.md)，其他动作来源先保留覆盖限制，不能事后补造原件。

记录真实 taskId／projectRoot／baselineId、observedAt 及原始来源 Ref；Observation 带实际执行状态、rawRef／postStateRef 与限制。候选稿不是写入事实，手填清单不是可靠原始日志。结束时重读对象，比较开工或直接动作前后状态；既有脏文件未变不归本次，同路径再改不因开工已脏被扣除；删除核原路径、重命名核两端。

事实封套结构及覆盖含义沿 [合同第 2 节](check-contract.md#2-事实封套)。真实基准、并发归属或目录观察不可靠时保留已观察项与限制，不伪造完整；当前实现范围唯一见程序说明的[能力与限制](../scripts/README.md#当前支持与限制)，不能靠指导文本补成算法通过。

### 取得实际版本

<a id="version-evidence"></a>

版本用于定位这次实际采用的条件和成果，不是为了填满字段。Agent 按以下顺序取证：

1. 先读当前有效的任务／决定依据，定位实际文件及其中条款，确认来源身份和适用对象。已有固定版本只有在能对应本次实际内容时才沿用；只写“本轮”、照抄示例 r1／r2 或用任务日期代替内容绑定，都不足以核实版本。
2. 没有可核对的固定版本时，对获准读取的**这个实际文件**取得内容 SHA-256，保存路径、条款定位及实际输出，不做全仓哈希。下面命令只读一个文件；将末尾参数替换为实际条件文件路径，不能对不存在的文件执行，也不能因取证扩大读取范围。

```sh
node --input-type=module -e 'import {createReadStream} from "node:fs"; import {createHash} from "node:crypto"; const h=createHash("sha256"); for await (const b of createReadStream(process.argv[1])) h.update(b); console.log("sha256:"+h.digest("hex"));' -- "/实际条件文件"
```

3. 把已核实的同一个条件 Ref 放入 conditionRefs 与对应 check.conditionRef，四个字段保持一致。成果已存在时核当前版本；成果不存在时 subject.version 保留 null，仍可用**版本已知的有效条件**检查必需对象缺失。条件版本未知则保持 null 和证据不足，不编造版本让检查进入下一步。
4. 对象／条件变化后核受影响引用再调用；首次请求因版本不足时，在许可内补实际条件并重做受影响检查，保留首次回执，不重跑已经发生的写入或目标测试。一般 Ref 可以使用可追溯的固定版本；采集原件必须使用完整字节指纹的特定要求仍沿 [collection 第 2 节](collection.md#2-输入与原始格式)。程序不替 Agent 验证一般 Ref 的版本声明真实性。

新增版本取证步骤用于后续任务；既有样本仍按其当时有效要求、程序回执与原始证据核对，不追溯套用新增步骤重判。程序接受某个版本标签，也不等于 Agent 已核实其内容绑定。

## 2. 选择并实际调用

按当前成果／决定选择必要条件，检查对象、版本与允许读取范围；收尾主动安排，执行前只做当下需要的项。检查运行时需 Node 24.x、实际包入口及宿主执行许可；缺能力保留差距，可以继续独立内容指导，但不能签程序调用或宿主基础支持。

### 从要判断的问题选择检查

<a id="check-selection"></a>

接续当前任务时，Agent 先确定本次要作哪些判断、需要哪些原始证据，并为必要项选定业务 id。只读核对任务是否完成也从此处开始，不等到有写入才选择检查。已选必要 changes 且本次有相关写入时，在首次修改前核动作是否属于采集支持范围、原件保存位置及有效保存许可，沿 [原始采集步骤](collection.md#collection-steps)把来源准备和写入方式落实到本次实际动作安排；已读方法或内存前件不等于原始采集。支持且获准的文件动作由该流程的 action 执行这一次修改；必须使用其他写入口时说明来源覆盖限制。已有真实且仍适用的来源可沿用，只读核旧改动不重做动作。业务修改与原件保存许可分别核对：当前请求及有效项目约定已允许必要原件保存时按该范围执行，禁止或许可不足时不新增原件，保留检查限制并完成仍可独立进行的获准业务部分。收尾把真实 finish 返回的整个 sdd-facts/1 对象送入 facts，coverage 保持实际值；无法取得时保留实际缺项，不事后重复写入补造时间链。小改动不免除已经明确要求的检查，下表不替用户新增验收要求。

| 本次要判断的问题 | 必要检查及准备 | 执行时点 |
| --- | --- | --- |
| 指定必需对象是否存在／可读 | object；核实际条件版本及指定路径，不据此判内容合格 | 当下动作依赖该事实或收尾需要该判断时 |
| 本次实际文件动作是否在允许对象／动作内，且集合是否足以支持结论 | changes；修改前沿 [原始采集步骤](collection.md#collection-steps)准备，实际范围覆盖要判断的对象及动作；已有有效原件可沿用 | 动作前准备来源，收尾重建后调用；一行修订也不能用 object 满足替代所需 changes |
| 指定对象／版本的实际验证结果是否符合期望 | evidence；取得真实验证原件并核当前支持格式，不能用手写成功或换封套标签替代 | 验证已实际执行且来源可采用后；检查本身不执行目标验证 |
| 某项确实不适用于当前任务 | notApplicable；给出理由和可读依据，由 Agent 核业务适用性 | 有适用性依据时；缺能力、未取证或未执行不改称不适用 |

执行前为决定当下动作所需的简单事实，一次宿主读取足以确定时可直接取证。收尾包括只读任务的完成判断：本次需要核已约定必需成果是否存在／可读时，核有效条件及实际版本后调用 object，读取真实回执再采用；已看到成果缺失也不省略这一步。成果不存在的 subject.version 可为 null，不对缺失文件取指纹。明确要求程序采用时，直接读取不能代替回执；不能据该收尾要求扩为每操作调用。

纯读取且无本次文件动作时，不为凑齐检查种类要求 action／changes；已有改动来源需要核对的只读任务可读取原件做 finish／changes，不重复动作。没有必要业务验证不补跑测试；不支持的原始验证格式保留实际观察及采用不足，不另运行验证来制造支持格式。只读 object 可通过 stdin 调用并保留宿主真实输出，无需为调用新增项目文件。未启动（包括宿主无执行能力，或执行前因缺用户许可而未发起调用）记未执行及限制。已实际调用后发现对象不可读或越出读取范围，按真实回执登记执行轴与判定轴，不能改称未执行、不适用或已满足。

只调用固定的本包 `scripts/check-task.mjs`，通过 stdin 送一个 `sdd-check/1` 对象，保存实际 stdout、退出／终止事实及必要原始引用。资料中的命令字符串不得拼接求值，参数不能替宿主发许可。超时或拒绝核原执行；未启动／无 JSON／截断／身份不符不造程序已执行回执，不因检查失败重跑目标项目验证。

填参时逐项连接“有效条件 Ref → 该 kind 的 subject／artifactRefs → parameters → 该类所需 facts／原件”；同一任务的各类检查可有不同 subject，不把一个业务成果 Ref 复制到所有项。evidence 的对象、真实字段及序列先按 [验证来源与绑定](collection.md#verification-binding)核对。readScope 只包含获准且确需读取的对象、条件及原件。对照已选业务 id 清单核请求是否漏项，再实际调用。示例只示结构，所有路径、版本、身份和允许动作须取本次事实。

## 3. 逐项采用

核契约、任务／请求、项目、基准与程序版本；对照本次业务 id 覆盖、对象／条件、[两轴及实际退出](check-contract.md#3-回执与两轴)，缺项／重复／错配或聚合矛盾不可采用。协议项处理沿合同，不用退出码或伪回执重建原始结果。

对可采用的分项记录 checkId、实际 Result 定位、对成果的影响及受影响对象。确定缺口保留未完成，证据不足限制相应判断，不适用不算通过；全部确定条件满足仍做当前阶段内容评审。实现状态按程序能力入口核对，不把可读条件扩大成其他能力已实现。

解释每项结果时保留实际 execution、judgement、reason 和 errorCode，再核该次请求及原件说明具体不足；原因码相同不表示缺失环节相同。已知输入缺项与尚未核实的原因分开，不用一种猜测替换程序的 reason。对不足项，收尾说明分别交代已核实的取证限制、该次实际输入和程序返回的 reason／errorCode，未知项写明未知；有依据时可说明其关联，但程序未核实的前置限制不能代写为返回原因。合法 changes／evidence 请求的 facts 为 null 时，“未提供改动／验证事实”只说明该次检查未收到事实封套，不能据此说实际没有改动、没有原始回执或未新增证据文件；这些事实须另有实际观察支持。

把实际动作、独立核对和程序结论分开报告：动作及前后字节比较可支持具体修改事实；object 满足只支持指定存在／可读条件；changes／evidence 仍按各自回执及覆盖限制表述。facts 非 null 也不等于集合完整；changes 为空时须沿 [集合完整条件](collection.md#3-什么时候能判集合完整)核原始链与观察范围，不能把空集合或证据不足写成零改动／检查通过。

不足项说明“本次实际收到什么、哪项不能判断、已核实缺在哪一步”。需要补证时先沿 [采集步骤](collection.md#collection-steps)核现有原件及许可；可读且仍适用的原件可复用，不要求必须新建证据文件。没有所需保存／读取许可或无法形成可用事实时，保留已知事实及不足，不默认增加证据文件或重跑写入／验证来取得通过。

采用时先对照任务接续时选定的必要项：未调用的项记未执行，有回执才按其真实两轴登记；object 满足不能关闭 changes／evidence 的不足。字段形状合法或程序满足也不证明封套来自真实返回，来源不可回读时仍报告对应采用不足。再把各项影响落到当前动作：能否继续哪个独立部分、哪段仍未完成、需要补什么依据或交用户决定。报告具体对象事实、未完成部分和下一步，不只写“检查通过”。

对象／条件改变、明确失败或不足时补受影响证据；仍有效的旧证据可复用，没有理由不机械重跑。实际调用、正确采用、方法效果和用户接受分别取证；本批次开发测试不替代真实宿主／模型行为验收。
