# 启动准备与已有项目接续

## 是什么、做什么、怎么做

启动准备明确当前项目、目标、有效材料与工作许可，使下一阶段有可信输入。按新建或已有项目接续开展，形成最小背景／范围、阅读入口和真实状态，不提前产出目标项目的十阶段文档。先读共用规则及 [阶段组织](../references/stage-methods.md)。

## 1. 判断模式和进入条件

接续核资料前先读 [需求贯通](../references/traceability.md)，定位本次具体原始要求／经确认的等效依据及已有唯一关系入口，核其覆盖范围和来源缺口；不补造 MRD、历史确认或需求关系。

核用户要做的事、产品对象、当前阶段、已有资料／成果与允许动作。新建先回述使用者、问题和预期效果；已有项目先读现行入口、需求／设计、决定、状态和相关实际成果，判断可以接续哪里，缺同名文件不代表全部重来。只读核对只报告，不创建协作文件。

Agent 核材料身份、现状并建议接续位置；用户决定目标、范围、重要未知及下一步。来源包作者的历史批准不是当前批准。材料有矛盾先呈现来源与影响，等待相关决定，独立盘点继续。

**本步落点与继续条件：**核对结果进入既有任务／状态记录；目标、资料身份和允许范围明确后继续准备，理解矛盾先交用户决定。

## 2. 整理最小工作基础

默认先做产品起点的最小回述、资料盘点与建议动作；工具约束目录、索引／状态、生命周期与保存身份等治理动作，仅在需要写入、已有治理结构或用户要求时触发，不默认新建目录或问卷式盘点。展示当前理解、可复用输入、关键缺口和建议准备动作，按当前许可执行。资料分类、重复版本和过期入口核实际内容，保留原件；当前用户已确认的目标／约束按 [需求记录](../rules/requirements.md)暂存，不把推断转成确认。

项目执行约定与 Agent 工具约束分开：沿用已有组织，工具约束使用项目根目录的独立文件夹，项目约定另置并相互引用；介入项目缺少该结构且确有需要时，报告缺口与建议，经用户同意后新建根目录工具约束文件夹及其入口／索引，指向既有唯一正文；不搬移、不重写既有治理与正文。只有需要时建立最小项目说明、索引与状态；内容唯一正文、当前许可与历史分开。读取完整采用来源，不能只放入口链接就说规则已读取或生效。

资产分为已有、规划和缺失；尚未形成的文档只列计划位置，不生成失效链接。命令、角色、钩子未实现时登记未配置，不用占位实现或空目录表示功能已有；实际实现入口的登记沿 [阶段组织](../references/stage-methods.md#成果入口与验证载体)。

资料职责、接手路线及版本盘点按[项目资料与版本治理](../references/project-governance.md#project-material-version-governance)落在已有入口／状态：定位本次相关文件的维护者、有效版本与确认范围，分清源码、验收制品、安装及公开副本的实际身份；历史观察不补成当前事实。已有项目先对账，只补当前任务必需缺口，不把治理模板复制成产品功能或整套目录。

不初始化产品源码、安装技能、添加适配器／钩子或调用外部服务，除非当前请求明确包含。目录存在不证明宿主自动发现；采用、显式读取、配置、自动加载和行为结果分别记录。

**本步落点与继续条件：**项目说明／索引／状态仅保存本次实际形成的内容；逐个重读确认正确写入后检查，写入失败不进入完成声明。

## 3. 实际检查与修正

按 [检查顺序](../rules/execution.md#9-检查动作与结论)实际核目标／范围符合用户意思、原始依据与关系入口覆盖本次接续范围、引用资料可读且身份正确、现行入口指向有效正文、状态与真实已做动作一致。结构核对不代替理解确认；未配置宿主不声称支持通过。

发现问题先按根因规则判断是理解、来源、版本还是入口问题，再修最小完整范围。缺关键目标只暂停依赖起草，说明最小需要澄清的事，不发泛化问卷。

## 4. 完成与实际阶段交接

交付已准备的目标／范围、资料与当前阶段依据、实际检查及限制，请用户确认指定准备成果。新建项目在取得 MRD 许可后，交目标、当前需求记录、有效来源／决定和未决影响给 [MRD](mrd.md)。已有项目按第 1 节核实的实际阶段及当前任务接续，交该阶段需要的现行成果／版本、原始依据及关系入口、决定、证据和缺口；仅补齐准备资料不把项目退回 MRD，也不重开未受影响的已通过阶段。若识别到实际既有缺陷修复，接续说明引用 [开发方法 §3](development.md#3-小范围实现与根因修复)的修前复现、修后同一复现核对；只读任务只给后续安排，不执行修复或测试。普通开发待办或新功能沿有效需求与验收安排实现验证，不套修前复现。

按目标项目既定评审方式核成果结论和接续许可；已有明确许可沿用，准备结果确认不自动授予其他阶段许可。实际阶段不明或关键输入冲突时，先说明候选阶段及依据，暂停依赖选择的动作，独立盘点继续。恢复时核现行资料／许可和未完成项，沿用有效决定，不重复初始化。

本阶段交接按[阶段交接物格式](../references/stage-methods.md#阶段交接物格式)组织：新建→MRD（目标、需求记录、来源／决定、未决）、已有→实际阶段（现行成果／版本、依据、决定、证据、缺口）；路径引用（现有需求／资料）。其余通用字段、五类状态与模板沿格式节。不复制正文。

## 5. 规则与历史身份交接

按 [三类约束](../rules/core.md#三类约束与采用边界)逐项定位已采用正文、固定版本、实际采用依据、维护者与冲突回退；项目内阶段操作细则归项目规则，提案不因同目录变为生效规则。已有项目先对账，不迁移来源原件或复制第二份操作正文。

在既有索引／状态中分别登记内容生命周期（草稿、当前、已替代、封存、历史证据）与保存身份（已提交、已跟踪未提交、未跟踪、有意排除）。旧批准绑定原固定对象，封存不自动重启；历史目录原位存在不等于入库。当前摘要与实际决定不符时修入口并保留旧版本，不把旧时点措辞继续当现状；行号必须注明提交或工作树观察身份。交接位置与检查沿 [阶段组织](../references/project-governance.md#当前摘要与历史)。历史文件操作步骤及项目版本计划／升版判定沿该文“历史文件操作入口”“项目版本计划与升版判定”。

**成果最小清单（完成前核对）：** ①当前项目／产品对象、目标与范围、非目标；②已有资料、有效版本、入口与缺口；③实际阶段、任务模式与写入许可；④至少一个可继续入口（新项目→MRD，已有→实际阶段）；⑤未决、风险与下一步；⑥不适用项依据。缺①—④标缺口，不默认记准备完成。
