# UI：用户能操作和理解的交互

## 是什么、做什么、怎么做

UI 把有效任务和组件状态转为用户可操作、能看懂的交互。根据真实通道选择图形界面、CLI、API 反馈或会话消息，不强制做页面。先流程、再状态／文案、低成本原型与任务演示、检查和交接；共用动作见 [阶段组织](../references/stage-methods.md)。

## 1. 输入、模式和责任

核 PRD 任务／验收、组件契约／状态、现有交互、目标用户与平台、本次设计／修订／只读范围。用户判断实际可用性、确认指定版本，Agent 提方案、制作获准样例、观察与核对；不能把自己读懂记为用户读懂。

记录通道选择的用户任务／平台依据；采用非图形通道时说明为什么无需图形界面。交互条目关联实际消费的具体需求／验收及组件契约，模块责任经真实组件关系追溯；不为补齐阶段伪造组件或中间节点，不把 UI 链接填入模块／组件列冒充组件，不另建全项目覆盖表。风险与实际入口沿 [共用载体](../references/stage-methods.md#成果入口与验证载体)。

**本步落点与继续条件：**对象／平台／状态来源及许可进入 UI 记录；能定位当前用户任务后设计流程。

## 2. 先展示一条完整任务

首次组织任务流程前，先读 [需求贯通方法](../references/traceability.md)。把当前任务的具体 PRD 行为／规则、验收及适用组件契约关联到操作与可见结果，说明交互怎样落实要求；按实际依赖直接消费输入，不伪造严格单线的阶段关系。

梳理入口、必要选择／输入、操作顺序、完成与退出，说明每步用户看什么、做什么、产品回应什么。展示当前能判断的具体流程并请用户纠正，重要业务变化回 PRD；普通布局选择连续设计，不把内部实现细节放进用户决策。多屏／多端先给任务入口—路径—退出和跨端状态，写端能力差异与降级；按适用补信息架构／导航。可用性测试记录参与者、任务、观察与限制，未执行不宣称通过。

**本步落点与继续条件：**流程与用户真实纠正进入 UI 草稿／记录；核入口到完成／退出连贯、必要行为决定已取得后做样例。

## 3. 可见状态、文案与原型

实际消费组件状态时，接收组件逐状态可见结果清单并按实际消费的行为／组件状态映射加载／成功／失败、未执行／不足、取消与未知等适用表现，缺清单记缺口；按真实依赖直接消费 PRD 时，不要求组件状态前置。同时说明可用操作、数据后果、恢复路径及具体依据。最小状态矩阵示例：状态｜触发｜用户看到｜可做操作｜数据后果｜恢复／退出。模拟示例：结果未知｜工具返回超时或无回执｜“结果未确认，已发出的动作需要核对”｜查看原动作、重新查询结果（不重复写入）、停止并人工核对｜可能已写入或未知｜保留原操作记录，按核对结果继续或退出。影响完成路径、数据后果、权限、可撤销性或可发现性的交互取舍由用户决定；纯视觉排布可连续设计。核大白话文案与契约的触发条件、权限和结果同义，专业交接仍保留这些精确条件。通道为 CLI／API／会话消息时，另给最小执行清单：明确反馈、错误／未完成、确认／取消、失败与接管、可执行下一步；非图形通道不以截图冒充演示。产品界面文案独立于 Agent 消息，写清发生什么、哪部分未完成、用户能做什么，不把 SCQR 叙事直接当界面文案。未知不展示成功，不承诺撤回已发生动作。必要影响和决定实际呈现，详情可按需展开，链接不替代关键消息。

文案按 [大白话与 SCQR](../references/messages.md)，具体说对象事实、哪段未完成、接下来做什么；不要让用户先理解内部术语才回答。输入说明／错误指向能改的地方，按真实平台核相关可访问性。按任务和许可选择文字／流程样例、线框或可操作交互原型并标模拟身份，不因设计原型安装框架或实现生产系统。

**本步落点与继续条件：**状态／文案、组件关系和模拟样例进入 UI 既有位置；核操作后果及可见影响一致后演示。

## 4. 用户任务演示

给用户一个清楚、可信、中立的任务目标，说明演示对象／条件，再观察理解和操作困难；不以“请确认你看懂了”的引导式回答当效果证据。用户表示要求含糊时先改任务说明，再记录实际反馈与影响，不让用户猜检查词值。

有能力和许可时操作原型；只有文本交流就记录文本范围。Agent 纸面走查、用户文字理解、可操作演示和真实产品运行分别判断，不把未开展演示说通过。反馈按根因定位是提示、流程、状态还是上游行为，再修直接关联并核受影响任务。

**本步落点与继续条件：**真实任务说明、观察和用户反馈进入演示记录，模拟身份保持；困难未解决先改相关对象，已核可交付范围后评审。

## 5. 检查、完成与交接

实际核用户任务可走通、状态／操作后果与有效行为及组件契约一致、关键提示已呈现、演示真实范围和反馈能定位对应任务／要求，再依 [检查顺序](../rules/execution.md#9-检查动作与结论)报告。未操作的原型不能记操作通过；设计缺口具体说明影响。

静态截图只支持对应布局／文案表达检查，不能独自证明流程可操作、后台保存、权限或真实工具执行；这些结论分别需要相应操作与回执。

交指定 UI／样例、实际承接条目、实际反馈、检查和未验证项，用户确认该版。获准后向 [开发](development.md)交流程、状态／文案、输入约束、实际组件关系及验收样例，定位各自有效正文与版本。UI 通过不等于产品验收／发布。无开发许可停止；恢复核现行任务、状态和反馈，不重做有效设计。

交接给开发的交接包按[阶段交接物格式](../references/stage-methods.md#阶段交接物格式)组织：PRD、组件契约与许可、UI 版本、样例／演示范围、可见状态与后果、演示参与者／范围与未执行状态、开发输入及路径引用；纸面设计、演示与运行分别标注。其余通用字段、五类状态与模板沿格式节。

## 6. 开发前可见后果交接

把当前任务的操作入口、输入限制、正常／相关异常可见结果、权限与数据后果、恢复／退出及组件来源作为可引用条目交交接包（供开发建包时形成当前开发包合同的[实施进入条件](../references/stage-methods.md#实施进入条件)）。正文唯一维护在本 UI，契约与业务要求分别引用组件／PRD；表面文案不得掩盖失败或未知。

Agent 检查可见反馈与底层状态相符，用户确认重要体验取舍及指定版；纸面设计、真实用户演示和产品运行分别记录。阻断实施的交互／行为缺口回责任层消除，独立包可继续；UI 确认不代签业务验收或工具许可。

**成果最小清单（完成前核对）：** ①任务入口—退出流程与多端差异；②实际适用的状态矩阵（未知／取消／失败等按适用）；③可见文案与操作；④交互取舍与体验判据；⑤通道／多端／平台依据、信息架构（如适用）；⑥演示或纸面走查证据与限制；⑦开发交接。缺①②标缺口，不默认记 UI 完整。
