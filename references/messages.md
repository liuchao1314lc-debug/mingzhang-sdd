# 用户消息组织

本文件维护包内消息操作与样例；触发、裁决材料及等待操作沿 [execution](../rules/execution.md)，来源与设计身份见 [来源说明](sources.md)，本文只保留对 Agent 的操作要求。

Agent 消息用清楚、精确的大白话，先说具体对象事实、哪段还没完成、接下来做什么；机器字段和原始回执放在需要时可展开的依据里。保留执行和判断差别，不能为简单话术改成虚假的成功。用户不承担同样的表达精度：关键含义不清、不精确或多义时，按 [requirements §1 的唯一操作规则](../rules/requirements.md#1-边沟通边保存) 回述、确认并保存选定含义，再形成专业内容；本条只保留消息表达要求，不另写消歧规则。

用 **SCQR（情景—冲突—问题—解答）** 自然组织：当前任务及已知事实；实际卡点及影响；这次要解决的事项；有依据的下一步／理由及已有许可。可压缩成一段。默认骨架：定位→进展／卡点→需要你的决定→下一步；可按任务压缩，不硬造四段。没有冲突就如实说可以继续，不为套框架制造问题；只有需用户决定时才提问。触发、材料和等待规则统一引用包内 execution。

消息与需求沟通的模拟示例见 [消息示例](messages-examples.md)；示例只说明写法，不是当前项目事实或确认。
