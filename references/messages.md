# 用户消息组织

本文件唯一维护包内消息操作及样例，是已确认沟通设计的运行转化；设计要求不在此重新批准。触发、裁决材料及等待操作沿 [execution](../rules/execution.md)，同一方案变化由制作维护者核设计与转化的一致性，使用者不依赖制作项目文档。

消息用清楚、精确的大白话，先说具体对象事实、哪段还没完成、接下来做什么；机器字段和原始回执放在需要时可展开的依据里。保留执行和判断差别，不能为简单话术改成虚假的成功。

用 **SCQR（情景—冲突—问题—解答）** 自然组织：当前任务及已知事实；实际卡点及影响；这次要解决的事项；有依据的下一步／理由及已有许可。可压缩成一段。没有冲突就如实说可以继续，不为套框架制造问题；只有需用户决定时才提问。触发、材料和等待规则统一引用包内 execution。

开工定位仍按[execution第1—5节](../rules/execution.md)触发和核对。以下为模拟的活动报名文案评审示例，各项内容应由当前任务的有效资料和许可填写，在对应实质动作前实际发送。

阶段定位：UI／交互设计｜报名提交失败提示的文案评审；任务模式为只读评审。

项目归属：活动报名项目 → 报名提交失败后的提示与重试引导。

来源标识：当前用户请求要求只读评审；已确认PRD r3规定失败后保留报名信息并允许重试，UI草稿 r1是本次评审对象。拟提出的文案调整属于建议，尚未采用。

范围确认：只读核对UI草稿中的失败提示与上述行为是否一致，交付问题、依据和文案候选；本次不改稿、不实施页面或运行测试。资料不足的部分说明缺口，当前评审不扩大为重新设计报名流程。

以下为模拟示例，需要换成当前真实对象及范围，不是固定业务或已发生证据：

- 文件可读而内容不完整：“PRD r2 能打开，但还没有写清失败后怎样提示、用户能做什么。我会按已有修订许可补这段，再核对应验收；现在不能交为完整成果。”
- 改动集合不足：“PRD r2 已写入，但记录还不足以确认本次是否只改了允许文件。先补核这次动作的前后记录；正文候选可继续评审，改动范围暂不能说已通过。”
- 协议不足：“检查请求用了程序不支持的版本，因此没有核任何业务文件。先按当前合同修正请求；这次回执不能证明文件或内容合格。”
- 超时未知：“检查调用没有完整返回；我先核原进程结果。它不会因此重跑目标项目测试或再次写入文件，已有成果仍保留。”
- 额度到界：“草稿保留，但批准的调用额度已用完，改动范围尚未核完。我会停相关检查并交已有结果；恢复前先核原结果、剩余额度及许可，未知用量不会填成零。”
- 交付确认：“PRD r2 已写入，失败提示和后续操作已补齐；本次改动范围核对仍未完成。我会在已有许可内补查记录。你确认的对象是该版正文，范围证据缺口另保留；下一阶段是否开展另按你的授权。”

机器 stdout 始终只保留原始 JSON；人读摘要由 Agent 实际发送。只在文件保存、消息草稿形成或链接存在时不算用户已看到；补发也不倒签及时呈现。

需求沟通也用真实记录表达，以下仍是模拟示例：

- 暂存：“你确认的‘取消后保留草稿’已保存到需求记录 R-03。保存内容是停止后续处理、草稿仍可编辑；已经发出的外部动作是否能取消还未确定，我会单独核对。”这句只能在实际写入并核对后发送。
- 冲突：“刚才新增的‘取消就删除草稿’与 R-03 的‘保留草稿’冲突，两者会导致不同结果。我建议默认保留，并提供用户主动删除；这需要你决定。相关取消规则暂不定稿，其他任务可以继续整理。”
- 收全：“目前这条任务的操作、取消结果和验收已列出，待决项已解决。请核对还有没有遗漏；你确认本阶段这份清单已收全后，我再起草正式 PRD。”已取得该确认就沿用，不再次提问。
